`driverwire` is the contract that lets a printer driver run in a module
process instead of inside the server. The server dials each printer through
the module as it dials a builtin driver, and the rest of the server cannot
tell the two apart.

Use this package when your module drives printers. The module's
[manifest](./manifest.md) declares `kind: driver` and a `driver` block with
the dialect and the baseline. A module's `main` is one call:

```go
driverwire.Run(ctx, driverwire.Options{Name: "mydriver", Version: "1.0.0", Build: build})
```

`build` returns a `connectorapi.Driver` that dials, built from the module's
settings. The server calls `driver.connect`, `driver.do` and the file calls on
the module. The module calls `driver.state`, `driver.content` and the other
reports back, and names them in its manifest's `require` block with the
`core-` prefix.

## `driverwire` {#driverwire}

```go
import "github.com/prusa3d/prusa-connect/sdk/driverwire"
```

Package driverwire is the connector contract on the plugin wire (ADR-20261123-sat). A printer driver runs in a module process, and the host reaches it through this package as it reaches a builtin driver.

The host calls driver.connect, driver.do and the file calls with a Client. The module answers them with a Module, which runs any connectorapi.Outbound. The module calls driver.state, driver.content and the other reports back, and the host answers them with the same Client. Run is the whole main of a driver module.
